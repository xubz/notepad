# CLAUDE.md

Notepad: a minimal, Windows XP Notepad–style macOS text editor. Swift + AppKit (TextKit 1), SwiftPM executable, no dependencies. Derived from arietan/lite-edit (MIT).

## Scope: keep it small

The feature set is deliberately limited to: New/Open/Save/Save As/Close/Exit, Find & Replace, Go to Line, line numbers, syntax highlighting, word wrap, font, line endings/encoding, and visible whitespace.
**Do not add** tabs, sidebars, file trees, quick open, git, projects, sessions, multi-cursor, plugins or settings windows unless explicitly asked.

## Build / run / verify

- `swift build`: debug build. Must stay free of warnings.
- `./build.sh`: release build packaged as `Notepad.app` (Info.plist from `Resources/`, icon generated by `Tools/make-icon.swift`). `--install` copies it to /Applications.
- Headless self-check (DEBUG builds only, see `DebugSnapshot.swift`):
  `NOTEPAD_OPEN=<file> NOTEPAD_SNAPSHOT=<out.png> [NOTEPAD_APPEARANCE=dark|light] [NOTEPAD_SAVE_TO=<file>] .build/debug/Notepad`
  This opens the file, renders the window to a PNG (no screen-recording permission needed), optionally saves a copy, then quits. With only `NOTEPAD_OPEN` set, the app opens the file and keeps running (that's what `.vscode/launch.json` uses).
- When launched directly (debugger or Terminal, not Finder or `open`), AppKit makes no Untitled window by itself; `AppDelegate` creates one if no document is open. Use it to check UI changes visually, and use `cmp` on the saved copy to confirm files round-trip byte-for-byte.

## Architecture (Sources/Notepad)

- `main.swift`: creates `DocumentController` first (it must be the shared controller), then runs the app.
- `DocumentController.swift`: maps every type to `TextDocument`; the Open panel accepts any file; opening a file replaces a blank, untouched Untitled window.
- `TextDocument.swift`: `NSDocument` subclass (`@objc(TextDocument)`, which `Info.plist` references). Owns the `NSTextStorage`. On read, it detects the encoding (`TextEncoding`) and line ending (`LineEnding`) and **normalizes the in-memory text to `\n`**; on write it converts back to the original ending and encoding. `autosavesInPlace = false` gives classic Save / Save As. Changes to line ending or encoding go through the undo manager, so they mark the document edited.
- `EditorWindowController.swift`: builds the window (gutter | scroll view, status bar below), manually sets up the TextKit 1 stack with `EditorLayoutManager`, wires the text view's undo manager to the document, applies settings, and handles highlighting scheduling plus the Format-menu actions.
- `EditorTextView.swift`: auto-indent on Return, app-wide font changes, and the column guide (drawn in `drawBackground`).
- `EditorLayoutManager.swift`: draws the whitespace and line-ending markers in `drawGlyphs`.
- `SyntaxHighlighter.swift`: `Language` detection plus regex rules. Colors are applied as **layout-manager temporary attributes**, so they never touch the text storage or undo. Rules come in two kinds: `tokens` are applied first; `spans` (comments and strings) form one alternation where the leftmost match wins and is applied last.
- `LineNumberView.swift`: gutter beside the scroll view. It converts text-view coordinates into its own, which handles scrolling and the find bar.
- `FormatMenus.swift`: builds the Syntax / Line Endings / Encoding menu items, shared by the Format menu (target nil) and the status-bar popups (target = window controller), so the two never drift apart.
- `StatusBarView.swift`: `Ln, Col` on the left; clickable language / line-ending / encoding buttons on the right (`onClick`).
- `Settings.swift`: UserDefaults-backed global preferences; changes post `.settingsDidChange`, and every window re-applies them.
- `Theme.swift`: Tango palette as dynamic light/dark `NSColor`s.
- `AppDelegate.swift`: the menu bar (built in code, no nib) and the global toggles.

## Conventions / gotchas

- Use `textStorage.mutableString` for NSString reads. `textStorage.string` / `textView.string` copy the whole buffer when bridged to Swift.
- Windows are not restorable (`isRestorable = false`), so launch always shows one empty Untitled.
- Settings can be overridden per run via the argument domain, e.g. `.build/debug/Notepad -columnGuide 80`.
- Find & Replace is the system `NSTextFinder` find bar (`usesFindBar = true`), so it handles undo correctly. Don't reimplement it.
- Files over 300K characters only highlight the visible region (`fullHighlightLimit`).
- The menu uses `@objc` protocol selectors (e.g. `UndoActions`) instead of `Selector("…")` strings to avoid warnings. Responder actions need the colon form (`undo:`).
